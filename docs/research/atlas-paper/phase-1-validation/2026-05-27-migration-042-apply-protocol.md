# Migration 042 — apply protocol

Date: 2026-05-27
Status: protocol (active)

The migration 042 SQL draft is generated by
`backend/scripts/propose_migration_042.py` from two inputs:

- `docs/research/atlas-paper/phase-1-validation/labels/llm-vocab-mining/2026-05-27-sonnet46-vocab.jsonl`
- `docs/research/atlas-paper/phase-1-validation/reports/llm-distillation/zero-shot-reasoning-mine.json`

The script does NOT touch the database. This document is the
operator-side checklist for applying it cleanly.

## Pre-apply checklist

1. Read the generated Markdown report:
   `docs/research/atlas-paper/phase-1-validation/reports/migration-042/migration-042-proposal.md`.
2. For each topic block, sanity-check three things:
   - **Cross-topic distractors**: any term that could apply to multiple
     topics has already been rejected by the script. Spot-check by
     scanning the `rejected_cross_topic_distractor` lists.
   - **Multilingual coverage**: confirm each topic gets terms in at
     least 3 languages. Topics with EN-only suggestions need a manual
     pass before applying.
   - **Negative monitors**: the `terms_to_monitor` lists capture false
     friends. They are NOT added by SQL. Save the markdown report as
     a reference for the next benchmark audit.
3. Read the SQL draft:
   `backend/migrations/042_llm_distilled_lexicon_expansion.sql`.
4. For any UPDATE block that looks too aggressive (>20 new terms,
   terms that overlap heavily with another topic), edit out the
   suspicious terms manually before applying.

## Apply via Supabase MCP

```text
mcp__supabase__apply_migration
  name=migration_042_llm_distilled_lexicon_expansion
  query=<contents of the reviewed SQL file>
```

## Post-apply: re-classify and re-benchmark

After mig 042 lands, the existing `signal_topic_assignments` rows still
reflect lexicon as of mig 041. Three steps to refresh and measure lift:

1. **Delete v2 assignments for the touched topics**:
   ```sql
   DELETE FROM signal_topic_assignments
   WHERE method = 'lexicon'
     AND model_version = 'theme-hint-lex-v2'
     AND topic_id IN (
       SELECT id FROM atlas_topics WHERE slug IN (<list>)
     );
   ```
2. **Re-backfill** the touched topics over a recent 24h window:
   ```text
   backend/scripts/backfill_lexicon_topics.py --window-hours 24
   ```
3. **Re-benchmark** against existing gold:
   - Reuse `backend/scripts/topic_benchmark_harness.py score` if you
     re-sample stratified rows for the touched topics.
   - Or compare Atlas v2 predictions on the existing 64 reviewed
     signals — the gold labels do not need to change, only Atlas's
     assignment changes.
   - Run `backend/scripts/benchmark_bootstrap.py` over the new gold
     to produce updated CIs.
   - Compare against the baseline `[46.50%, 70.46%]` Wilson CI from
     batches 01 + 02 to measure lift.

## Rollback

If the post-apply Wilson CI lower bound drops below the prior baseline,
revert by deleting v2 assignments for the touched topics and reverting
`atlas_topics.lexicon_terms` to the pre-042 snapshot. The snapshot at
`backend/data/atlas_topics_snapshot_2026-05-25.json` does not currently
contain `lexicon_terms`; before applying 042 the operator should refresh
the snapshot with a full taxonomy dump via Supabase MCP `execute_sql`:

```sql
SELECT slug, label, lexicon_terms, gdelt_theme_hints
FROM atlas_topics
WHERE is_active = TRUE
ORDER BY slug;
```

Save the output as
`backend/data/atlas_topics_snapshot_pre_042.json` for rollback reference.

## Promotion gate (paper-grade)

Per Paper 1 promotion gate documented in
`docs/research/atlas-paper/2026-05-27-methodology-paper-outline.md`,
Atlas v2 should reach the following before the migration is treated
as production-grade:

- Overall Wilson CI lower bound >= 65% (developing).
- Wilson CI lower bound >= 85% on at least 50% of touched topics
  (minimum gate per-topic).
- No global regression on other topics' `high_conf` count.

If the gate fails, the migration still ships as a documented
experiment, but the paper's distillation section will report the
specific topics where LLM-distilled vocabulary did not lift Atlas
precision and discuss the limitations.
