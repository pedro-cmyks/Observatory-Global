## Judgment — the number is an artifact; the finding underneath is real

This run does NOT measure the engine. It measures the **starved centroid
pool**: v2 anchors exclusively on active `dynamic_topics` centroids, and
post-collapse the pool held **16** (+2 new = 18). 15,000 signals forced into
16 bins at `assign_t=0.82` (the promiscuous end of the measured cliff:
0.82 → 98.6% assignment) produces generic-attractor blobs — median assigned
sim 0.865, black-hole 21%, "coverage 96.4%" that is really force-fit. The
2026-06-29 A/B that PASSED (v2 coherence 0.930 > 0.908, 103 topics ≥3) ran
on a healthy pool. Same engine, opposite verdicts — the discriminating
variable is substrate health, not engine design.

**The real F4 finding: v2's serving quality is COUPLED to dynamic_topics
pool health with no floor.** Had the cutover been live during this week's
collapse, prod would have served 18 blob-topics while v1's lexicon lanes
kept 324 alive. v1 degrades gracefully (lexicon lanes are
substrate-independent); v2 as built does not.

## Consequences for the F4 flip criterion

Flip stays gated on the §11 metrics PLUS, now explicit:

1. **Substrate-health precondition**: pool >= ~80 active centroids (the
   06-29 regime) before any A/B counts as evidence; assign_t must be
   re-measured against pool size (0.82 is only sane with a rich pool).
2. Structural fix candidate (next engine session): v2 should anchor on the
   FULL R3 spine — atlas categories + scoped-snapshot topics — not only
   dynamic centroids, so a dynamic-pool collapse cannot hollow it out.
3. Re-run the A/B in 2-3 days once tonight's scoped snapshots rebuild
   persistence (mechanical re-run; small-model-safe).
