# Atlas — Go-To-Market Plan (2026-07-06)

**Inputs (Pedro, this session):** end-state = **business/startup**; network = **cold**
(no analyst access today); infra = **tied to the M1** (substrate crons run on
Pedro's machine, bus factor 1).

**Product state (from telemetry + L1/L2/L3 deep reviews):** motor técnicamente
fuerte y honesto (gate v3, semantic lane, 6.9M-vector archive, voice-mix
ownership, dossier v2 who-says-what). **Usuarios externos: 0.** PMF no medido
(N=1). El riesgo del proyecto ya NO es técnico — es demanda no probada +
imposibilidad actual de servir a un extraño.

---

## The forced sequence

Cold + M1-bound + business ambition means the order is not a choice:

1. You cannot sell what dies when your laptop sleeps → **infra first**.
2. In cold, nobody logs into an unknown tool → you earn attention with a
   **demonstrated result**, not a signup page → **insight-led cold start**.
3. Attention → design partners → retention loop → only then pricing.

Skipping any step burns the leads the next step generates.

---

## Phase 0 — Make it servible + pick the wedge (weeks 1–3, BLOCKING)

Not marketing. Prerequisite to everything.

- **Infra off the desktop.** Substrate pipeline must survive Pedro's machine
  sleeping. Minimum bar: move the crons to an always-on box OR harden with
  watchdogs + an honest public status/staleness banner so a stranger never
  sees stale data served as live. (Recurring incident class: insight dead 6
  days, crons dead 20h, matview dead 13h — for you a bug, for a first-time
  user it's the last visit.)
- **Accounts (minimal)** + **shareable dossier URL.** Pins in localStorage die
  with the device today — no retention, no distribution. The dossier is the
  atom of value AND the distribution object; it needs a public link.
- **Security blindaje (BLOCKING sub-gate, Pedro's call).** Before any external
  user touches the app. Attack surface, ranked:
  1. **SQL injection** — the backend hand-builds raw SQL in many places (CTEs,
     `unnest`, `slug--cc` parsing, country/person filters, the free-text
     research/plan query, translate headlines). Audit every path where user
     input reaches a query; anything interpolated (f-string/.format/concat)
     instead of bound (`$1`) is a hole. Highest-severity surface.
  2. **Unauth expensive endpoints (cost + DoS)** — research/plan embeds ~100
     candidates per open; translate/insight hit OpenAI/DeepSeek/Anthropic. An
     anonymous user hammering these = cost explosion + embed starvation. Gate
     behind auth + per-IP/user rate limits.
  3. **Authz on user data** — once accounts + pins/investigations are
     user-scoped, enforce row ownership server-side (Supabase RLS), never
     client-side only.
  4. **Secrets** — no keys in the frontend bundle (Vite exposes VITE_*); .env
     never committed; rotate the keys that have leaked/expired historically.
  5. **Prompt injection** — LLM prompts built from untrusted headlines + user
     queries (translate/insight/typing). Bound outputs; lower severity (labels/
     prose, not actions) but scope it.
  6. **XSS** — audit any raw-HTML render of headlines/translations in the
     frontend.
- **Pick the beachhead persona** (recommendation below). Wedge case = the Phase
  1 flagship investigation (see below), not a list of thin cases.

**Exit gate:** (a) security audit clean on injection + expensive-endpoint
exposure; (b) a stranger on another device can open a dossier link, see live
(or honestly-labeled) data, and it doesn't break. Until BOTH pass, no outreach.

## Phase 1 — Insight-led cold start (weeks 3–10)

The engine for a founder with no network. Do NOT pitch the tool. Publish the
findings the tool produces. Pedro's reframe: the hero is ONE deep, rigorous
investigation — not 2–3 thin cases.

### 1a — The flagship investigation (the hero artifact)

A serious piece of work, produced over real time (not a screenshot dump):

- **Pick one live, consequential topic** and investigate it END TO END in Atlas,
  exercising every surface — universe/orbital, narrative threads, country brief,
  voice-mix (who-says-what, self-voice vs foreign), coverage gaps ("what's
  missing"), time-as-dimension replay, and the dossier. Screenshot each finding
  in context (panels, views, configs).
- **Independently verify each Atlas finding against the open web**, with time —
  document what Atlas surfaced that a normal web/news search could NOT reach
  (the India election-legitimacy eval is the template: Atlas pointed at a real
  crisis unreachable from a Peru-first search, web-confirmed).
- **Output** = a flagship write-up: "What Atlas saw that search couldn't" —
  narrative + screenshots + the verification trail. This is the eval doc turned
  into a public artifact. It is simultaneously the demo, the proof, and the
  top-of-funnel.

This doubles as the honest PMF test: producing it forces you to use every
surface as a real analyst would, and exposes where the workflow breaks.

### 1b — Cadence (after the flagship lands)

- 1 shorter public analysis / week in the same dossier format, each ending in a
  shareable dossier link.
- **Channel:** where OSINT/conflict researchers already are — Bluesky/Twitter
  OSINT circles, relevant subreddits, Bellingcat-adjacent communities. Cold
  outreach rides on the *finding*, not the *product*.

**Metric:** flagship reach (reads, shares, inbound from target-persona
accounts); then dossier link opens by non-Pedro devices. Target: 3–5 genuine
analyst conversations by week 10.

## Phase 2 — 5 design partners (weeks 6–12, overlaps Phase 1)

Convert the inbound into high-contact partners.

- **Session:** 30 min, recorded, THEY bring their own topic. You watch where
  they stall. India case is the warm-up demo, not the whole session.
- **Single metric:** do they reach the value moment (investigation → dossier)
  **without you steering?** Target: 3 of 5 return on their own within 7 days.
- Build ONLY what these five prove missing. The Phase 3 retention loop below is
  the near-certain answer.

## Phase 3 — Retention loop (weeks 10–16)

The mechanism that turns curiosity into habit — the biggest product gap for the
"situational awareness" job.

- **"Tell me when MY topic changes"**: alerts / email digest / push on a saved
  watch. Saved Watches exists but doesn't notify — that's the whole gap.
- Without this there is no retention; without retention no GTM spend pays back.

## Phase 4 — Distribution via artifact + pricing (post-retention)

- The shareable dossier IS the growth channel: an analyst pastes the link in
  their newsroom → value proof + acquisition in one object. Don't pay for
  distribution until the artifact spreads on its own.
- **Pricing** only after retention is real: design partners free → cheap
  prosumer tier for individual analysts → team/newsroom tier later. Too early
  to fix numbers; the design-partner conversations set willingness-to-pay.

## Beachhead recommendation

The wedge names four personas (journalist, OSINT/conflict researcher, newsroom
desk, policy/NGO analyst). For **cold + solo + business**, start with the
**OSINT/conflict-research community**:

- Most reachable cold (they congregate publicly on Bluesky/Twitter/Reddit).
- Highest value fit for "who says what across countries/languages + what's
  missing" — that's their daily job.
- Most likely to **amplify publicly** → your cold-start engine compounds.

Narrow further once telemetry from real partners shows which sub-persona sticks.
Anti-goal holds: no new surfaces during GTM.

## The risk that kills it

Optimizing the engine instead of proving demand. The engine is done enough. The
only work that de-risks the business now is: (0) make it servible, (1) put
findings in front of strangers, (2) watch 5 of them use it. Everything else —
more surfaces, more motor calibration — is procrastination dressed as progress
until there is a second user.
